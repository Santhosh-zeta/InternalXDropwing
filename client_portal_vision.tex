\section{Product Vision Goals}
The Client Portal must not feel like a basic dashboard or file-sharing page. It is designed to become the client's primary collaboration space with Dropwing Groups, replacing scattered communication across WhatsApp, email, Google Drive, and other third-party platforms. The portal is clean, premium, transparent, and easy to use while exposing only information that is intended for the client.

    \item Pending Invoices Ledger

    \item Open Support Tickets
    \item Recent Deliverables Link

\section{Strict Security \& Tenant Isolation Rules}
\begin{tcolorbox}[colback=red!5,colframe=red!60!black,arc=6pt,boxrule=1.5pt,title=CRITICAL SECURITY POLICY]
Clients must \textbf{NEVER} see or have access to any of the following internal operations:
\begin{itemize}
    \item Internal Developer Notes \& Private Communications
    \item Internal Team Discussions \& Resource Allocation
    \item Employee Performance Ratings
    \item Venture Profit Margins \& Internal Financial Analysis
    \item Internal Venture Risks \& Management Strategy
    \item Management Comments not explicitly shared with the Client
    \item Cross-client or Cross-tenant Information of other ventures
\end{itemize}
\end{tcolorbox}
To enforce this security policy, the backend implements server-side role-based access controls (RBAC) and strict database tenant isolation. Every database query returning client-facing data must be dynamically isolated using the venture identifier verified against the client session:
\begin{equation}
\text{SQL Security Policy: } \sigma_{\text{venture\_id} = \text{session\_venture\_id}}(\text{Entity})
\end{equation}
Any attempt to query data without a matching \texttt{venture\_id} check or requesting administrative tables will result in an immediate authorization failure.
